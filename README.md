# Календарь звонков

[![hexlet-check](https://github.com/StepanovCode/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/StepanovCode/ai-for-developers-project-386/actions)

Учебный проект сервиса бронирования календаря, разрабатываемый совместно с ИИ.
Реализованы создание типов событий в открытой админке и публичный каталог
с хранением в PostgreSQL. Выбор времени и бронирование выполняются следующими
тикетами. Тесты, линтеры и сборка запускаются в Docker.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Стек

- Окружение: Docker Compose, Node.js 24.21.0, npm 11.19.0, Go 1.27.1.
- Frontend: Vite, React, TypeScript, Tailwind CSS, shadcn/ui.
- Backend: Go и Gin, слои API, usecase, services, repo и domain.

## Установка

На хосте нужны Git, Docker с Compose v2 и Make. Node.js, npm, Go и зависимости
проекта запускаются в контейнерах; устанавливать их на хост не требуется.

```bash
git clone https://github.com/StepanovCode/ai-for-developers-project-386.git
cd ai-for-developers-project-386
make start
```

Перед запуском откройте Docker Desktop или запустите Docker Engine.
`make start` собирает образы, останавливает ранее запущенные сервисы,
устанавливает зависимости в контейнерах, применяет миграции отдельной командой
и запускает приложение в фоне.
Команда подходит для первого и повторного запуска; первый запуск требует
интернета и может занять несколько минут. Создавать `.env` необязательно.
Для остановки выполните `make down`. Быстрый повторный запуск без установки
зависимостей — `make up`. Проверки запускаются отдельно: `make check`.

Frontend доступен на [localhost:5173](http://localhost:5173)
и backend на [localhost:8080/api/health](http://localhost:8080/api/health).
`GET /api/health` возвращает HTTP 200 и `{"status":"ok"}` напрямую и через
[proxy Vite](http://localhost:5173/api/health).
Отдельный запуск: `make frontend-dev` и `make backend-dev`.
После изменения Go-кода повторите `make backend-dev`: он пересобирает
бинарный файл и перезапускает backend. Frontend использует HMR.

Проверка production-сборки:

```sh
make frontend-build
make frontend-preview
```

Preview доступен на [localhost:4173](http://localhost:4173), пока команда
работает; остановка — Ctrl+C. Сначала запустите `make up` или
`make frontend-dev`. Preview предназначен для локальной проверки сборки.

По умолчанию зарезервированы порты 5173, 4173 и 8080 на loopback хоста.
Для изменения скопируйте `.env.example` в `.env` и отредактируйте внешние порты.
Корневой `.env` читает Compose; в приложения он автоматически не передаётся.
Файлы `.env` исключены из Git, безопасный пример сохраняется.

## Команды окружения

```sh
make help
make frontend-shell
make backend-shell
make frontend-run CMD="node --version"
make backend-run CMD="go version"
make down
```

`make down` сохраняет данные PostgreSQL, зависимости и кеши. `make clean-volumes` явно удаляет
также volumes этого проекта, включая все типы событий; после очистки повторите
`make start`.

## Проверки и исправления

Все проверки выполняются в одноразовых контейнерах и не требуют `make up`:

```sh
make check          # линтеры, типы, форматирование, тесты, сборка обеих частей
make frontend-check # проверки только frontend
make backend-check  # проверки только backend
make test
make database-test  # HTTP/PostgreSQL integration, отдельная одноразовая тестовая БД
make lint
make typecheck
make format-check
make app-build
```

Проверки не исправляют исходники. Для явного исправления используйте
`make format` (Prettier и gofmt) и `make lint-fix` (доступные исправления
линтеров). Тесты завершаются после одного запуска и подходят для CI.
Сборка создаёт `frontend/dist/` и `backend/bin/api`; оба каталога исключены из Git.

## Типы событий и PostgreSQL

Публичный каталог — `/book`, страница типа — `/book/{uuid}`. Открытая админка
`/admin` содержит навигацию типов и встреч; форма создания —
`/admin/event-types/new`. Доступ без авторизации — согласованное ограничение
учебной версии. Список встреч пока обозначен следующим этапом.

Имя владельца задаётся `OWNER_NAME` (по умолчанию Дмитрий Степанов), id —
`default`. Подключение backend задаётся `DATABASE_URL`; по умолчанию используется
сервис `postgres`, без опубликованного порта. Локальные реквизиты Compose
предназначены для разработки. Эти параметры можно задать в корневом `.env`.

```sh
make migrate        # запустить БД и применить очередные миграции
make up             # обычный запуск: таблицы не пересоздаются
make database-test  # отдельный postgres-test/booking_test, те же миграции
```

Миграции `backend/internal/repo/migrations/NNN_*.sql` добавляются в конец
последовательности. Уже применённый SQL не редактируется: runner хранит SHA-256
и останавливается при несовпадении. Выполнение сериализуется advisory lock,
SQL и запись версии фиксируются одной транзакцией. Данные хранятся в volume
`postgres_data`; начальный каталог пуст, демонстрационные данные не создаются.
Тестовая БД находится в другом сервисе с tmpfs и не подключена к приложению.
Интеграционные тесты отказываются работать с адресом обычной БД.

## О Хекслете

[Хекслет](https://ru.hexlet.io/) — школа программирования: авторские программы обучения с практикой, поддержкой наставников и реальными проектами, которые остаются в резюме. Этот репозиторий — один из таких проектов.

### Рабочее расписание и календарь

`WORK_SCHEDULE` — JSON-объект с ключами `mon`, `tue`, `wed`, `thu`, `fri`,
`sat`, `sun`. Значение каждого дня — список интервалов `start`/`end` в `HH:MM`:

```dotenv
WORK_SCHEDULE='{"mon":[{"start":"09:00","end":"12:00"},{"start":"13:00","end":"18:00"}],"wed":[{"start":"09:07","end":"18:00"}]}'
```

Все часы относятся к Europe/Moscow; отсутствующий день закрыт. Пустое значение
переменной включает стандартное пн–пт 09:00–18:00, `{}` закрывает все дни.
Интервалы сортируются, пересечения и переход через полночь отклоняются при запуске.
`24:00` допустимо только как окончание рабочего дня (полночь следующей даты),
в качестве начала не допускается. Праздники не учитываются.

GET `/api/event-types/{id}/slots` возвращает сегодняшнюю московскую дату и
следующие 13 дат, включая пустые списки. Сетка 15 минут начинается от каждого
интервала; встреча целиком помещается в нём, начало минимум через 30 минут
по серверным часам включительно. Все типы владельца участвуют в занятости;
стыки встреч разрешены. Ответ содержит только время и статус, без контактов.
Бронирования для автоматических проверок создаются исключительно в отдельной
`postgres-test/booking_test`. Таблица добавлена миграцией 002; пользовательское
создание и ограничение пересечений PostgreSQL реализуются в следующем тикете.

Календарь `/book/{id}?date=YYYY-MM-DD` восстанавливает выбранную дату из ссылки,
показывает месячную сетку и свободные слоты. Без действительной даты выбирается
ближайшая свободная; время нужно выбрать явно. Перед «Продолжить» SDK повторно
проверяет точное начало. Переход на `/book/{id}/details?date=…&slot=…` выполняется
без перезагрузки страницы. На этом шаге пока обозначена форма следующего тикета;
контакты гостя в URL не передаются.
