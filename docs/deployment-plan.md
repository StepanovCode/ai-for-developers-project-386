# План production-образа и деплоя

Дата: 2026-10-11. Основа: актуальный `origin/main`, ветка `codex/docker-deploy`.
Пользователь разрешил локальную реализацию согласованного плана. Push, merge
и создание внешних сервисов пока не разрешены; настройки Render передаются
пользователю после локальной проверки.

## Решения

- Корневой многостадийный Dockerfile собирает React/Vite и два Go-бинарных
  файла (API и миграции). Итоговый образ запускается непривилегированным
  пользователем без исходников, Node.js, Go и bind mounts.
- Единственный Go HTTP-сервер раздаёт frontend и API на `PORT` (8080 по
  умолчанию). `STATIC_DIR` указывает на готовую сборку. Без него остаётся
  прежний API-only запуск разработки.
- SPA fallback работает для GET/HEAD клиентских маршрутов. API, отсутствующие
  assets, скрытые файлы, каталоги и другие HTTP-методы не получают index.html.
- Без `DATABASE_URL` сервер запускает интерфейс и технический health endpoint;
  операции с данными возвращают 503 JSON, без фиктивных данных и хранилищ.
  Compose уже явно передаёт строку подключения. Заданный, но неработающий URL
  сохраняет fail-fast поведение. Условия скрытой проверки Хекслета неизвестны;
  запуск только с PORT проверяется самостоятельно.
- Production entrypoint применяет существующие миграции при заданном
  `DATABASE_URL`, затем запускает API через exec. Ошибка миграций прекращает
  запуск. Миграции не выполняются при сборке образа. Dev `make migrate`
  остаётся отдельной командой.
- PostgreSQL запускается вне образа. Локальная проверка использует отдельную
  тестовую сеть и БД с теми же миграциями; рабочая БД не изменяется.
- На Render: Docker runtime, корень репозитория, `./Dockerfile`, один регион
  для web и PostgreSQL, переменные PORT/DATABASE_URL/OWNER_NAME/GIN_MODE,
  health `/api/health`. Free PostgreSQL ограничен 30 днями. До публикации
  ветки Render не сможет собрать её изменения.

## Основные границы проверки

SPA не перехватывает `/api` и ошибки API. Отсутствующие JS/CSS не возвращают
HTML с 200. Прямое открытие вложенных страниц работает. Секреты/локальная
сборка не входят в Docker context. PostgreSQL сохраняет данные вне контейнера
приложения. Health без БД — liveness, а не подтверждение работы бронирования.

## Результат локальной работы

Обе архитектуры (linux/arm64 и linux/amd64) собраны и запущены; PORT=9090
и PORT=10000 подтверждены. make check и make database-test прошли;
после исправления ревью повторный make backend-check прошёл. Новые HTTP
и config тесты сначала обнаружили отсутствующие возможности. Отдельный
RED воспроизвёл HTML 200 для /missing.css/ и /missing.js/child, затем GREEN
подтвердил исправление. Ревью также исправило quoting команды для zsh
и исключение pem/key/secrets из Docker context.

На одноразовой PostgreSQL проверены миграции, создание типа, слоты,
бронирование, подтверждение, список встреч, busy slot и сохранность после
restart API. Ошибки PORT, реквизитов БД и checksum миграции завершили образ
с exit 1; SIGTERM завершил API с exit 0. Рабочая БД не изменялась.
Браузер подтвердил интерфейс, Manrope и список встречи из тестовой БД.

Render MCP проверен реальным list-workspaces: доступен My Workspace.
Внешние сервисы не создавались. make commitlint принял сообщение нового
коммита; make commits-check отклонил существующий main-коммит PR #22
с некорректным заголовком. После публикации PR #24 пользователь поручил
полностью убрать проверку истории; она удалена, проверка заголовка PR
и Conventional Commits для новых сообщений сохранены.
Публичная ссылка и проверка внешнего деплоя остаются невыполненными.
