# Спецификация приложения «На связи» — версия 1

Source: https://github.com/StepanovCode/ai-for-developers-project-386/issues/14

## Версия и статус

Версия 1 от 2026-10-05 утверждена пользователем. [Факт явного утверждения](https://github.com/StepanovCode/ai-for-developers-project-386/issues/13#issuecomment-6000597414). Содержательные требования версии 1 после утверждения не изменялись. Можно отдельным запросом переходить к декомпозиции на тикеты. Эта issue — спецификация, а не тикет реализации.

Карта решений: #3. При противоречиях старых решений применяются явно перечисленные ниже замены из решения API.

## Цель и границы

«На связи» — учебное приложение: гость выбирает тип события и свободное время и бронирует встречу с одним владельцем без регистрации. Владелец создаёт типы и видит предстоящие встречи всех типов.

Владелец предзадан конфигурацией: id default, имя «Дмитрий Степанов». Имя можно менять через конфигурацию; редактирования профиля в интерфейсе нет. Админка открыта: любой по её адресу может создавать типы и видеть встречи с контактами гостей. Адрес не является защитой. Регистрации, авторизации и нескольких владельцев нет.

Не входят: редактирование/удаление/архивация типов, отмена/перенос/редактирование бронирований, внешние календари, видеосвязь, письма и напоминания, подтверждение email, отдельные аккаунты гостей, платежи, фильтры и пагинация, настройка расписания через интерфейс, праздники и исключения на отдельные даты. Репликация, высокая доступность, резервные копии и восстановление утраченного хранилища исключены для учебного проекта.

## Термины и данные

- Владелец календаря — человек, с которым гости бронируют встречи.
- Гость — человек без аккаунта, оформляющий бронирование.
- Тип события — шаблон с названием, описанием и длительностью.
- Слот — интервал для встречи выбранного типа; длительность определяется типом.
- Бронирование — оформленная встреча на конкретное время.
- Предстоящая встреча — бронирование с началом строго позже текущего времени. В момент начала исчезает из списка, но сохраняется в БД.
- Расписание — общие рабочие дни и часы владельца.
- Окно записи — сегодня и следующие 13 календарных дат по Москве.

### Тип события

UUID v4 создаётся сервером и неизменяем. Название обязательно, одна строка, 1–100 символов; одинаковые названия разрешены. Описание обязательно, 1–2000 символов, обычный текст с переносами, без HTML/Markdown. Пробелы по краям удаляются перед проверкой длины, внутренний текст сохраняется. Длительность — целое число 1–480 минут. Тип можно создать, даже если для его длительности нет подходящих слотов.

### Бронирование

Имя гостя — одна строка, 1–100 символов после удаления пробелов по краям. Email обязателен, до 254 символов, проверяется формат без подтверждения владения. Телефон и комментарий не добавляются. Один email может использоваться для нескольких бронирований.

Сохраняются серверный UUID v4, ссылки на тип и владельца, имя/email гостя, начало, окончание и время создания, снимок названия и длительности типа. После сохранения бронирование сразу подтверждено; одобрение владельца не требуется. Выбор слота и заполнение формы не резервируют время. Прошедшие бронирования не удаляются автоматически.

## Время и занятость

Источник текущего времени — сервер. Часовой пояс расписания и всех экранов — Europe/Moscow, явно указан в интерфейсе; автоматического перевода в пояс гостя нет. Даты в интерфейсе показываются как ДД-ММ-ГГГГ. Технические форматы передачи и хранения определяются при реализации, сохраняя однозначность моментов времени независимо от часового пояса компьютера или контейнера.

Расписание по умолчанию: понедельник–пятница, 09:00–18:00, без перерыва. Рабочие дни и интервалы меняются конфигурацией и общие для всех типов. Интервалы внутри одного дня, без перехода через полночь; праздники не учитываются.

Алгоритм слотов:
1. Определить сегодняшнюю дату по Москве; окно — она и следующие 13 календарных дат, включая выходные. Это не 336 часов от текущего момента. В полночь окно сдвигается.
2. В рабочих интервалах сформировать начала с шагом 15 минут от начала каждого интервала.
3. Рассчитать окончание по длительности типа. Вся встреча должна помещаться в рабочий интервал и окно; окончание ровно на границе допустимо.
4. Начало не раньше чем через 30 минут от текущего серверного времени; ровно 30 минут допустимо.
5. Для допустимых по времени интервалов определить занятость по бронированиям всех типов. Занятые показываются недоступными, без сведений о гостях. Недопустимые по расписанию/длительности/сроку интервалы не предлагаются.
6. При POST бронирования заново проверить сетку, окно, расписание, срок и пересечения. Не округлять и не подменять недопустимое время.

Любое пересечение запрещено: интервалы учитываются как [начало, окончание), встреча может начинаться ровно в момент окончания предыдущей. Буферов нет. Запрет действует независимо от типа, имени и email гостя и обеспечивается PostgreSQL, а не только проверкой в приложении.

Примеры: в 10:07 ближайшее начало по стандартному расписанию — 10:45; в 10:00 допустимо 10:30. Для 45 минут последнее начало — 17:15 с окончанием в 18:00. Если занято 10:00–11:00, запрещены вложенные, частично пересекающиеся и охватывающие интервалы; 09:30–10:00 и 11:00–11:30 разрешены при соблюдении остальных правил.

Из двух конкурентных допустимых запросов на пересекающееся время сохраняется один. Приоритет не определяется открытием календаря или нажатием кнопки. Проигравший получает 400 / SLOT_UNAVAILABLE.

## Пользовательские истории и критерии экранов

### Гость: главная и каталог

На / сохраняется главная «На связи». Описание: «Выберите тип встречи и удобное время. Забронируйте встречу без регистрации и лишней переписки». Возможности: «Выбор типа встречи», «Выбор свободного времени», «Бронирование без регистрации». Кнопка «Записаться» ведёт на /book, ссылка «Админка» — на /admin.

На /book — имя владельца, заголовок «Выберите тип события» и каталог от старых типов к новым. Карточки на широком экране в две колонки, вся карточка кликабельна. Название и длительность видны полностью; описание — первые три строки с многоточием. На странице типа описание полное, переносы сохраняются. Поиск и фильтры не нужны.

### Гость: дата, слот, форма

На широком экране страницы типа — три колонки: сведения о встрече и выборе; календарь; слоты с кнопками «Назад» и «Продолжить». На телефоне — вертикально в этом порядке.

Календарь — месячная сетка с количеством свободных слотов под датами. Выбираются даты в окне 14 дней; переход между месяцами доступен, если окно пересекает границу. Изначально выбрана ближайшая дата со свободным временем. Слот выбирается явно; занятые интервалы имеют текстовый статус и недоступны.

«Продолжить» открывает отдельный шаг имени и email с итогом встречи и кнопками «Назад» и «Забронировать». Возврат к слотам сохраняет введённые данные. Тип и дата восстанавливаются из прямой ссылки; у страницы типа и шага ввода отдельные адреса. Имя/email в URL не попадают. Перед продолжением доступность проверяется заново.

### Гость: результат и ошибки

После успеха форма очищается, открывается отдельная страница подтверждения по UUID. Она загружает результат с сервера и работает после reload. Показывает номер бронирования, название типа, дату, начало/окончание, часовой пояс и имя владельца. Имя/email гостя не показывает.

При занятом/устаревшем слоте имя/email сохраняются, слот сбрасывается, варианты обновляются. Нет автоматического переноса на другое время. Для занятого времени: «Это время уже занято. Выберите другой слот».

При сетевой ошибке результат неизвестен: «Не удалось узнать результат. Повторите попытку». Идемпотентности нет. Если запись сохранилась, а ответ потерялся, повтор может показать занятость без восстановления подтверждения. Такое ограничение явно принято для учебного проекта. Ключи попыток, хранение попытки ради восстановления результата и прежняя блокировка формы до определённого результата не требуются.

### Владелец

/admin содержит «Типы событий» и «Предстоящие встречи». Создание типа — отдельная форма названия, описания и длительности. После успеха возврат к списку с сообщением «Тип события создан»; тип сразу виден в публичном каталоге. При ошибках ввод сохраняется, ошибки полей рядом с ними.

Общий список встреч всех типов: ближайшие сверху, без ограничения 14 днями, без фильтров и пагинации. Поля: название типа, дата, начало/окончание, длительность, имя/email гостя. Над списком указан часовой пояс. Загрузка при открытии, возвращении во вкладку и кнопке «Обновить», без периодического опроса. Уже загруженная встреча исчезает при наступлении начала.

### Общие состояния и доступность

- Пустой каталог: «Пока нет доступных типов событий».
- Нет свободных слотов выбранной даты: «На эту дату нет свободного времени»; можно выбрать другую дату.
- Нет времени во всём окне: «Нет доступного времени в ближайшие 14 дней».
- Пустой список встреч: «Предстоящих встреч пока нет».
- При загрузке — индикатор, при ошибке — сообщение и «Повторить». Ошибка не маскируется пустым списком.
- Неизвестный тип: «Тип события не найден» со ссылкой на каталог. Неизвестное бронирование: «Бронирование не найдено». Неизвестный маршрут: «Страница не найдена».
- Весь путь доступен с клавиатуры, фокус виден, поля подписаны, статусы не только цветом. После перехода фокус у заголовка шага, при ошибке формы — у первого ошибочного поля.
- На узком экране и при масштабе 200% нет потери содержимого и горизонтальной прокрутки страницы.

## Хранение и архитектура

React/TypeScript/Vite и Go/Gin, frontend и backend в отдельных каталогах. Инструменты, зависимости, линтеры, тесты, сборка и генерация запускаются в Docker. Проектные зависимости глобально на хост не устанавливаются.

PostgreSQL — отдельный сервис Compose с постоянным volume. Типы и бронирования переживают остановку, перезапуск, пересоздание контейнеров и обновление приложения. Последовательные миграции в репозитории запускаются отдельной Docker-командой; применённые не редактируются. Обычный запуск не пересоздаёт таблицы. Начальный каталог и бронирования пустые, демонстрационных данных нет. Тестовые данные только в тестовом окружении.

По умолчанию один backend и одна БД. Дополнительные backend используют общую БД и одинаковую конфигурацию; гарантии действуют для общей БД. Ссылки на существующий тип обеспечиваются БД. Успех возвращается после подтверждения сохранения. При недоступности БД — явная ошибка, без принятия бронирования во временную память. Удаление volume означает потерю данных; резервное копирование/восстановление не входят в требования.

Слои backend: api → usecase → services → repo, прямой вызов repo из usecase допустим через интерфейс потребителя. Конкретный доступ к PostgreSQL только в repo. usecase/services не импортируют реализации repo; services не зависят от usecase. domain независим от HTTP и хранения. Gin, HTTP DTO и генерируемые типы остаются в api; внутрь передаются context.Context и обычные типы. Сборка зависимостей в cmd/api. Не создавать сервисы, которые только перенаправляют вызов. Генерируемые HTTP-модели не определяют структуру хранения.

## API и генерация

JSON-поля camelCase. ID типов/бронирований — UUID v4 сервера; владелец сохраняет default. Ограничения полей перечислены выше.

| Метод и путь | Назначение и результат |
|---|---|
| GET /api/event-types | Каталог типов, 200 |
| POST /api/event-types | Название, описание, длительность → 201 и созданный тип |
| GET /api/event-types/{id} | Данные типа, 200 |
| GET /api/event-types/{id}/slots | Всё окно 14 дней, 200 |
| POST /api/bookings | eventTypeId, startsAt, guestName, guestEmail → 201 и подтверждение |
| GET /api/bookings/{id} | Подтверждение без контактов гостя, 200 |
| GET /api/meetings | Предстоящие встречи с контактами гостей, 200 |
| GET /api/health | 200, {"status":"ok"} |

Каталог общий для гостя и админки. Ответ слотов содержит границы окна, часовой пояс и все даты, у каждой список интервалов startsAt/endsAt со статусом available или busy. Даты без интервалов имеют пустой список. Подтверждения POST и GET одинакового формата: UUID, название типа, начало/окончание, часовой пояс и имя владельца. Backend определяет владельца, длительность и окончание.

| Статус ошибки | Назначение |
|---|---|
| 422 | Валидация, включая сломанный JSON |
| 400 | Занятый или недопустимый слот; для занятости code SLOT_UNAVAILABLE |
| 404 | Конкретный тип/бронирование не найдены |
| 500 | Неожиданная серверная ошибка |

Ошибки содержат code и message; fieldErrors допустим только при валидации, иначе отсутствует. Подробности БД остаются в логах. Пустой список — 200, не ошибка. Ключа Idempotency-Key нет.

TypeSpec — источник истины. Цепочка: TypeSpec → OpenAPI 3.0.0 → Hey API SDK и oapi-codegen. Сервер генерирует models, gin-server, strict-server, embedded-spec. Запросы проверяет gin-middleware; стандартные ошибки middleware адаптируются к согласованным статусам/формату, в том числе 422 для разбора JSON. Бизнес-логика остаётся ручной за API-границей.

Контракт/OpenAPI — api/, SDK — frontend/src/api/generated/, серверные артефакты — backend/internal/api/generated/. make generate выполняет всю цепочку в Docker и останавливается при ошибке. Точные версии закрепляются после проверки совместимости при реализации. Generated-файлы хранятся в Git вместе с контрактом и вручную не меняются. Актуальность проверяется при подготовке изменений. Повторной генерации и проверки diff в CI нет. Цепочка ещё не проверена запуском.

## Тестирование и приёмка

Go testing/httptest, Vitest/React Testing Library; E2E-инструмент не добавляется. Автоматические проверки в Docker через Make, включаются в CI с существующими проверками. Конкретные новые команды оформляются при реализации.

Время в автоматических тестах задаётся явно, без ожидания реальных часов. Интеграционные тесты используют отдельную PostgreSQL с теми же миграциями; создают/очищают данные только там. Конкуренция — два параллельных допустимых HTTP-запроса на пересечение: один 201, один 400 / SLOT_UNAVAILABLE, одна запись.

| Сценарий | Проверка | Критерий |
|---|---|---|
| Поля типа/гостя, сломанный JSON | Go HTTP | 422 и формат ошибки |
| Неизвестный объект | Go HTTP | 404 |
| Пустые каталог/список | API + frontend | 200 и пустое состояние |
| Расписание, 14 дат, полночь, 30 минут, длительность | Go с заданным временем | Только допустимые интервалы |
| Пересечения разных типов и стыки | Go + PostgreSQL | Пересечения запрещены, стыки разрешены |
| Конкурентные запросы | HTTP + PostgreSQL | Один успех и одно бронирование |
| Устаревший/занятый слот | API + frontend | 400, ввод сохранён, слот сброшен, варианты обновлены |
| Предстоящие встречи | Go + frontend | Сортировка и исчезновение начавшихся |
| Формы/загрузка/ошибки | Vitest / RTL | Правильные состояния и сохранение ввода |
| Генерация | Локально в Docker | Команда работает, SDK/backend собираются |
| Полный путь, reload/прямые ссылки, узкий экран, клавиатура, 200% | Вручную в браузере | Все истории доступны |
| Перезапуск приложения/PostgreSQL | Вручную в Docker | Типы и бронирования сохраняются |

Полный путь: владелец создаёт тип → гость выбирает тип/дату/слот → заполняет форму → получает подтверждение → владелец видит встречу. Браузерная приёмка, перезапуск и повторная генерация не добавляются в CI. Отменённые гарантии ключей попыток не тестируются.

## Замены прежних решений и трассируемость

Эта версия сохраняет согласованные требования, кроме явно заменённых:
- Все встречи по 30 минут → длительность каждого типа 1–480 минут.
- Неопределённый доступ к админке → открытая админка без авторизации.
- Ключи попыток, уникальность/хранение ключей, атомарное сохранение вместе с ключом, безопасные повторы и восстановление неизвестного результата → исключены для учебной версии решением API.
- Повторная генерация без diff в CI → локальная генерация и проверка при подготовке изменений.
- Браузерный E2E → ручная приёмка.
