# Главная страница «На связи»: план реализации

> **Для исполнителя:** после подтверждения пользователя применять
> `superpowers:executing-plans` для выполнения в этом чате либо
> `superpowers:subagent-driven-development`, если пользователь выберет делегирование.
> До подтверждения изменять только документы проектирования.

**Цель:** заменить техническую стартовую страницу описанием сервиса и добавить
переход к временной странице записи.

**Архитектура:** существующий React frontend, общая шапка и два экрана.
Обычные ссылки `/` и `/book` с выбором экрана по `window.location.pathname`;
новая библиотека маршрутизации для этого объёма не нужна.
API и состояние бронирования отсутствуют.

**Стек:** существующие React, TypeScript, Tailwind, shadcn/ui Card и Lucide;
проверки Vitest и React Testing Library в Docker.

**Спецификация:** раздел «Следующая задача: главная страница»
в [плане проекта](../../project-plan.md). Термины —
[GLOSSARY.md](../../../GLOSSARY.md), границы продукта —
[ADR-0001](../../adr/0001-limited-booking-scope.md).

## Ограничения

- Имя «На связи» и тексты из спецификации входят в согласование этого плана.
- Главная представляет сервис в целом; предупреждение о разработке на ней не нужно.
- `/book` — только заглушка, бронирование выполняется в будущих задачах.
- Админка, авторизация, БД, API, выдуманные слоты и новые зависимости не входят в работу.
- Инструменты frontend запускаются только через Docker/Makefile.
- Версии приложения, backend и workflow Хекслета остаются без изменений.

## На что обратить внимание при проверке

1. Прямой вход и перезагрузка `/book`: остаётся заглушка, а не главная.
2. `/book/` и параметры запроса: открывается та же страница записи.
3. Обе ссылки «Записаться» и возврат: адреса правильные, Back/Forward работают.
4. Узкий экран 320–390 px и масштаб 200%: текст и кнопки не обрезаются.
5. Клавиатура: все ссылки достижимы, фокус виден, декоративные иконки
   не дублируют доступные названия.

## Задача 1. Главная страница и переход к заглушке

**Интерфейсы:** сохранить default export `App()` без параметров;
внутренние компоненты `SiteHeader()`, `HomePage()` и `BookingPlaceholder()`
возвращают JSX. Все остаются в `App.tsx`, пока это небольшой статический интерфейс.
Существующий `main.tsx` не требует изменений.

- [ ] **1. Проверить исходное состояние.** Прочитать статус Git, спецификацию,
  глоссарий и ADR. Сохранить чужие изменения. Убедиться, что Docker доступен.

- [ ] **2. Обновить проверку пользовательского перехода.** В `App.test.tsx`
  проверить главный заголовок «На связи» и обе ссылки с именем «Записаться»:
  `expect(link).toHaveAttribute('href', '/book')`.
  Для путей `/book`, `/book/`, `/book?from=home` через настоящий
  `window.history.replaceState` проверить заголовок заглушки
  «Онлайн-запись скоро появится» и ссылку «На главную» с `href="/"`.
  После каждого теста возвращать адрес `/`; cleanup уже настроен проектом.

- [ ] **3. Запустить `make frontend-test`.** Убедиться, что новые проверки
  падают из-за отсутствия новых экранов, а не из-за окружения.

- [ ] **4. Реализовать экраны в `App.tsx`.** Воспроизвести композицию и тексты
  спецификации, использовать существующий Card и Lucide.
  Выбирать заглушку для `/book` и `/book/`, главную — для `/`.
  Применять обычные ссылки; query string не участвует в выборе страницы.
  Декоративным иконкам установить `aria-hidden`, использовать один h1 на экран.

- [ ] **5. Оформить страницы и метаданные.** В `index.css` добавить стили
  сервисных экранов, сохранив существующую основу shadcn.
  На широком экране — две колонки в контейнере около 1152 px,
  ниже 768 px — одна колонка; боковые отступы не меньше 16 px.
  Проверить контраст текста и видимый focus-visible. В `index.html`
  обновить title и description согласно спецификации.

- [ ] **6. Выполнить контейнерные проверки.** Запустить `make frontend-format`,
  затем `make frontend-check`. Ожидается успешное завершение ESLint,
  TypeScript, Prettier, всех frontend-тестов и production-сборки.

- [ ] **7. Проверить в браузере.** Открыть главную при ширине 1400, 390
  и 320 px, проверить масштаб 200%, переходы с обеих ссылок, возврат,
  Back/Forward, прямой вход и перезагрузку `/book`, Tab и Enter.
  Проверить консоль и отсутствие горизонтальной прокрутки.
  Повторить прямой вход `/book` на Vite preview собранного frontend.
  Если браузерная проверка недоступна, явно записать это ограничение.

- [ ] **8. Завершить проверку и журнал.** Выполнить `git diff --check`,
  просмотреть diff на соответствие объёму и записать реальные результаты
  в `docs/project-plan.md`. Представить пользователю результат.
  Публикация, деплой и создание PR не входят в этот план.
