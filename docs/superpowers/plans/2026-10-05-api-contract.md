# API-контракт и генерация — план реализации

> Исполнение: `superpowers:executing-plans`, в текущей сессии.

Цель: выполнить [тикет 15](https://github.com/StepanovCode/ai-for-developers-project-386/issues/15)
по [утверждённой спецификации 14](https://github.com/StepanovCode/ai-for-developers-project-386/issues/14).
TypeSpec в `api/` порождает OpenAPI 3.0.0, Hey API SDK и Go API-границу.
Работает health; бизнес-обработчики остаются следующим тикетам.

## Ограничения и решения

- Генерация, зависимости, тесты и сборки только в Docker; версии точные.
- Все восемь операций описаны; generated-файлы сохраняются в Git.
- HTTP DTO остаются в `backend/internal/api`; БД и бизнес-слои не добавляются.
- JSON camelCase; моменты RFC 3339 с обязательным смещением, даты YYYY-MM-DD;
  календарь Europe/Moscow, ответы моментов в UTC.
- Ошибки code/message; fieldErrors только для 422. Не раскрывать внутренние ошибки.
- Новые тесты подхватываются существующим CI; генерация в CI не добавляется.
- Существующие локальные документы сохраняются. Работа на отдельной ветке
  в текущем checkout; публикация, закрытие Issues и релиз в задачу не входят.

  Docker Compose и `make generate`. Описать модели, ограничения, ответы;

  для сломанного JSON/невалидных полей. Подключить generated strict Gin server,
  gin-middleware и адаптацию ошибок. Health возвращает status=ok; временные
  бизнес-обработчики дают явную 500 без фиктивных результатов.
- [x] SDK: тесты реального generated SDK на HTTP-ответы и сетевые ошибки,
  затем вызов health из приложения. Проверить вызов к настоящему backend
  через Vite proxy. Не менять экраны бизнес-сценариев.
- [x] Приёмка: `make generate` дважды без изменения артефактов, `make check`,
  независимое ревью, документация команд/версий и журнал проекта.

## Особое внимание при проверке

- Сломанный JSON, пустое тело, неверный Content-Type и UUID дают 422.
- Дробная длительность, границы длин, переносы в однострочных полях,
  email, даты без смещения и неизвестные поля не обходят контракт.
- Trim предшествует ограничениям длины; внутренний текст сохраняется.
- Ответы 400/404/500 и panic не раскрывают внутренние детали и fieldErrors.
- SDK передаёт отмену запроса, корректно обрабатывает HTTP и сетевые ошибки.

- Исходные frontend (4) и backend тесты прошли в Docker.
- Спецификация и тикет прочитаны; блокировок нет. Точные технические форматы

  отсутствии адаптера. Тест вызова из приложения падал без запроса health.

- Решение: TypeScript генератора закреплён на 6.0.2; 7.0.2 несовместим с
  используемым compiler API Hey API. Go runtime закреплён на 1.7.0.
- Решение: автоматическая нормализация закрытых схем перед обоими
  генераторами устраняет несовместимость kin-openapi. Тест лишнего поля
  сначала дал 500 (валидация пропустила его), после исправления — 422.
- Повторный `make generate` завершился успешно; SHA-256 OpenAPI, SDK и
  Go-артефакта совпали. Ошибки TypeSpec/SDK останавливали цепочку.
- Frontend: 8 тестов, линтер, typecheck, форматирование и сборка прошли.
  Backend: линтер (0 issues), gofmt, тесты и сборка прошли.
- `make api-smoke` прошёл через реальный Vite proxy. Он использует exec
